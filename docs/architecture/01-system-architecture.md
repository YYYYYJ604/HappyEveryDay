### 1.2 架构核心原则

| 原则 | 说明 |
|------|------|
| **分层架构** | 严格遵循经典三层架构（展现层 - 业务层 - 数据层），层间单向依赖 |
| **模块化** | 按业务域拆分模块，每个模块自治独立 |
| **DDD 驱动** | 核心业务逻辑采用领域驱动设计 |
| **CQRS 模式** | 查询与命令分离，数据库读写分离 |
| **防御性编程** | 所有外部输入必须校验，异常有兜底处理 |
| **可观测性** | 全链路日志追踪 + 性能监控 + 错误告警 |

## 2. 架构分层说明

### 2.1 客户端层 (Client Layer)

| 平台 | 技术 | 说明 |
|------|------|------|
| iOS | Flutter 3.41 | Dart 编译为原生 ARM64 |
| Android | Flutter 3.41 | Dart 编译为原生 AOT |
| Web | Flutter Web (PWA) | CanvasKit 渲染模式，支持离线功能 |
| 桌面 | 视未来需求 | 基于 Flutter Desktop 扩展 |

**关键能力**：
- 离线缓存：使用 Hive + SQLite 实现核心数据的离线可用
- 本地 AI：使用 TensorFlow Lite 做简单情绪识别
- 推送集成：对接 FCM/APNs/JPush

### 2.2 API 网关层

```yaml
网关能力矩阵:
  SSL终止: TLS 1.3, HTTP/2, HSTS
  限流:
    全局: 1000 req/min
    用户级: 100 req/min
    AI接口: 20 req/min
  鉴权: JWT Token验证 (前置校验)
  缓存: 静态资源CDN缓存 7天
  WAF: SQL注入/XSS/CSRF防护
  日志: 全请求访问日志录制
  熔断: 服务不可用自动降级
```

### 2.4 缓存策略

| 缓存层级 | 技术 | 缓存内容 | TTL |
|---------|------|---------|-----|
| 浏览器缓存 | Service Worker | 静态资源、API响应 | 视资源类型 |
| CDN缓存 | Nginx/Kong | 图片、字体、公共数据 | 7天 |
| 应用缓存 | Redis | Session、热点数据 | 30min |
| 数据库缓存 | PostgreSQL Shared Buffer | 频繁查询 | 自动管理 |
| 客户端缓存 | Hive/SQLite | 用户数据、聊天记录 | 永久 |

### 2.5 数据流向

```
用户操作 → Flutter App → Dio HTTP请求
    ↓
API Gateway (鉴权/限流)
    ↓
NestJS Controller (参数校验)
    ↓
NestJS Service (业务逻辑)
    ↓
├── Repository → TypeORM → PostgreSQL + PostGIS
├── Cache Layer → Redis
├── External API → DeepSeek API
└── Storage → MinIO/S3
    ↓
统一响应格式 → API Gateway → Flutter App
    ↓
Riverpod State更新 → UI重构
```

## 4. 技术选型与决策

### 4.1 技术栈全景

| 层级 | 技术 | 版本 | 选型理由 |
|------|------|------|----------|
| **前端框架** | Flutter | 3.41 | 跨平台一致性、高性能渲染、年轻化UI |
| **状态管理** | Riverpod | 2.x | 编译安全、无 BuildContext 依赖、测试友好 |
| **路由** | GoRouter | 14.x | 声明式路由、DeepLink支持、ShellRoute嵌套 |
| **网络** | Dio | 5.x | 拦截器链、重试机制、REST/WebSocket双支持 |
| **后端框架** | NestJS | 10.x | 模块化、TypeScript、装饰器驱动、企业级 |
| **ORM** | TypeORM | 0.3.x | TypeScript先行、迁移支持、Active Record模式 |
| **数据库** | PostgreSQL | 15 | 成熟稳定、JSONB支持、GEO扩展 |
| **空间数据** | PostGIS | 3.3 | 位置服务、空间查询、距离计算 |
| **缓存** | Redis | 7.x | 高性能、数据结构丰富、Pub/Sub |
| **AI引擎** | DeepSeek API | - | 成本低、中文优化、多轮对话强 |
| **对象存储** | MinIO | latest | S3兼容、自建可控、成本优势 |
| **容器化** | Docker + K8s | - | 标准化部署、弹性伸缩 |

### 4.2 关键决策记录

| 决策ID | 决策内容 | 替代方案 | 理由 |
|--------|----------|----------|------|
| ADR-001 | 使用 Riverpod 而非 Bloc | Bloc, GetX | 编译期检查、无模板代码、Provider组合灵活 |
| ADR-002 | 使用 TypeORM 而非 Prisma | Prisma, Sequelize | NestJS原生集成、装饰器模式统一 |
| ADR-003 | 使用 PostgreSQL 而非 MongoDB | MongoDB | 复杂关联查询、事务一致性需求、PostGIS |
| ADR-004 | 使用 DeepSeek 而非 OpenAI | OpenAI, Claude | 中文效果优、成本极低、数据安全 |
| ADR-005 | 使用 MinIO 而非阿里云OSS | 云厂商OSS | 自建可控、避免厂商锁定、开发测试一致 |
| ADR-006 | WebSocket 用于 AI 聊天 | 轮询、SSE | 实时性要求、双向通信、流式响应需求 |

### 5.2 JWT 认证流程

## 6. 可扩展性设计

### 6.1 水平扩展方案

| 组件 | 扩展策略 | 状态共享 |
|------|----------|----------|
| NestJS 实例 | 无状态 + 横向扩展 | 通过 Redis 共享 Session |
| PostgreSQL | 主从读写分离 + 分表分库 | 规避跨库关联查询 |
| Redis | Cluster 模式 (3主3从) | 槽位自动迁移 |
| MinIO | Erasure Coding (EC:4+2) | 自动数据分布 |
| WebSocket | Redis Pub/Sub 广播 | 多实例连接同步 |
